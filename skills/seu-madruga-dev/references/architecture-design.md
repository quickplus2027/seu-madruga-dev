# Architecture and design routing
First preserve existing architecture and conventions. For new product: state boundaries, contracts, persistence, error states, auth, observability, tests, deployment and rollback. Avoid speculative generic abstractions and unused dependencies. For visual tasks, consult project's visual standards if available, but use sophisticated motion/3D only when relevant and measurable. A lean product may still be artistically excellent: clean typography, hierarchy, accessible interactive explanations, progressive disclosure, responsive layouts and purposeful motion. Never load a whole visual encyclopedia when fixing a backend method. Prefer SVG/icons over emoji in product UI if project policy requests it; don't force this in prose or code semantics. Respect reduced-motion, keyboard, mobile and performance budgets.
